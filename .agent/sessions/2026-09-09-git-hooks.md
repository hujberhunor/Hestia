# 2026-09-09 — git hooks

## Task
Add portable pre-commit git hooks: format Python and YAML, and build every kustomization before a commit.

## Decisions
- **Use the pre-commit framework, not plain shell hooks** — the user wants portability. The framework pins tool versions and builds the tool environments on each machine.
- **ruff format for Python, prettier for YAML** — the user chose this pair. Both are fast and widely used.
- **Format scope: YAML in k3s-stack/, Python in app/** — the two code areas that matter. Ansible YAML and the skill Python stay out of scope.
- **kustomize build runs on every kustomization in the repo** — the user wants it repo-wide for the future, not scoped to the format paths.
- **prettier mirror is rbubley/mirrors-prettier, not the pre-commit one** — the pre-commit/mirrors-prettier repo is archived and stops at prettier 3.1.0. The rbubley fork is maintained.
- **kustomize hook is a local script, not a registry hook** — kustomize has no pre-commit registry hook. scripts/kustomize-check.sh calls kustomize, or kubectl kustomize as a fallback.
- **Empty layer dirs get a kustomization with resources: []** — the cluster kustomization references infra, services, and apps. An empty but valid kustomization in each builds clean and unblocks the commit. Each layer gets real resources later.

## Thesis note
The kustomize build step is the one part that is not fully portable. A pre-commit hook cannot vendor a binary, so each machine needs kustomize or kubectl. This is a real limit of commit-time infrastructure checks.

## How pre-commit works in this repo

### Flow
1. `git commit` triggers `.git/hooks/pre-commit` (written by `pre-commit install`).
2. The framework loads `.pre-commit-config.yaml` at repo root.
3. It runs each hook in order:
   - **ruff-format**: Formats `^app/.*\.py$`. If it changes a file, the commit fails — you run `git add -u` and `git commit` again.
   - **prettier**: Formats `^k3s-stack/.*\.ya?ml$`. Same behavior as above.
   - **kustomize-build**: Runs `scripts/kustomize-check.sh`. It builds every `kustomization.yaml` in the repo. If any build fails, the commit fails and prints the error.
4. If all hooks pass (or after you re-stage failed changes), the commit proceeds.

### You run these commands one time on each machine
```bash
pip install pre-commit    # or: pipx install pre-commit
pre-commit install        # writes .git/hooks/pre-commit
```

### Ports
- `pre-commit` — the hook runner. Python, pip-installed. Portable (version-pinned in config).
- `ruff` — Python formatter. Installed by `pre-commit` from the pinned `astral-sh/ruff-pre-commit` repo. Portable.
- `prettier` — YAML formatter. Installed by `pre-commit` from the pinned `rbubley/mirrors-prettier` repo. Portable.
- `kustomize` or `kubectl` — build checker. Must exist on each machine. The script prefers `kustomize`, falls back to `kubectl kustomize`. This is the one non-portable piece.

### Manual runs (optional)
```bash
pre-commit run --all-files      # run all hooks on every tracked file
pre-commit run                  # run hooks on the files your commit includes
```
